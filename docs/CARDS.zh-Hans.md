# 卡片参数总表

`hoymiles` 集成捆绑的八张 Lovelace 卡片的完整参数说明。

[English](CARDS.md) · **简体中文**

---

## 卡片如何加载

集成启动时会把八张卡片全部注册为前端模块，因此**无需手动添加资源**，也不依赖任何
CDN。用 **添加卡片 → 手动** 粘贴 YAML，或直接写进仪表盘 YAML 文件即可。

集成安装完并重启 Home Assistant 之后，卡片类型为 `custom:hoymiles-*`。

> 改过卡片文件？请硬刷新浏览器（`Ctrl` + `F5`）。

## 通用参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `dev_id` | string | 设备标识 `<client_prefix>-<SN>`（如 `MSA-280520260806`）。除仪表盘卡片（按实体取值）外均为**必填** |
| `language` | `en` \| `zh` \| `de` | **可选覆盖**：卡片默认使用工具栏语言切换选的语言（默认英文）；只有需要把某张卡片钉死为某种语言时才填。 |
| `title` | string | 卡片标题，各卡片默认值不同（见下文） |
| `show_title` | bool | 设为 `false` 隐藏标题（部分卡片同时隐藏设备 SN） |

`dev_id` 的作用：卡片据此推导出所需实体 id（`sensor.<dev_id 转下划线>_<后缀>`）。
如果你的实体命名不符合这个规律，用各卡片的 `entities:` 映射单独覆盖。

### 语言是怎么选的

支持三种语言：**英文**、**简体中文** 和 **德文**。

1. **语言切换只有一个，在 Home Assistant 顶部工具栏里** —— 就在“添加 / 搜索 / 语音 /
   编辑”那排按钮的左侧，所以本集成生成的仪表盘每个视图都能看到。选
   `English` / `中文` / `Deutsch` 任意一个，**页面上所有卡片立刻一起切换**。
   选择存在浏览器里（`localStorage["hoymiles.language"]`），刷新后依然有效，
   本集成其它仪表盘也共用它。
2. **默认英文**。卡片**不再**跟随 Home Assistant 界面语言：仪表盘经常被共享、
   挂在墙上做面板，或者截图给别人看，所以由**看的人**决定语言。
3. 卡片配置里显式写了 `language: en` / `language: zh` / `language: de` 时，
   **以它为准**（只对那一张卡片生效）。只有需要把某张卡片钉死语言时才写。
4. 语言是在渲染时解析的，所以选完**所有卡片实时跟着变**，不用刷新页面、也不用改配置。

> 切换语言只重绘文字，不影响数据：切换后数值照常刷新。

> 这个切换框在工具栏里，而工具栏属于 Home Assistant、不属于卡片，所以由
> `hoymiles-lang.js` 注入 —— 它是本集成启动时注册的文件之一。离开 Lovelace
> 仪表盘（比如进入设置页）就没有那个工具栏，也就没有切换框。

> 还没翻成德文的句子会回退到英文，而不是显示空白 —— 部分翻译永远不会比不翻更差。

> `hoymiles-gauge` 是例外 —— 它内部没有任何文案，上面的字全部来自你配置的
> `name` / `label` / `icon`，永远不需要翻译。给 `name` 一个映射，它就跟其他卡片
> 一样跟随语言：
>
> ```yaml
> name:
>   en: PV today
>   zh: 今日发电
>   de: PV heute
> ```

### 让自己写的文字也跟随语言

上面的规则只管卡片**内部**的文案。你在 YAML 里写的文字（卡片标题、曲线名、
gauge 的 name、`balancer_label`）是你自己的，卡片无法翻译 —— 但可以在你提供的
多个语言之间选择：把**字符串换成映射**即可。

```yaml
type: custom:hoymiles-history-chart
# 原来： title: History
title:
  en: History
  zh: 历史数据
series:
  - entity: sensor.x_pv_power
    name:
      en: PV power
      zh: 发电功率
```

卡片按解析出的语言（`en` / `zh` / `de`）取值。映射里**没有**当前语言时，先回退
`en`，再回退到任意一个已有的条目，所以残缺的映射也不会变空。普通字符串行为完全不变，
因此**现有仪表盘全都不受影响**。

支持语言映射的参数：

| 卡片 | 支持映射的参数 |
|---|---|
| 所有卡片 | `title` |
| `hoymiles-history-chart` | `title`、`series[].name` |
| `hoymiles-gauge` | `name`、`label` |
| `hoymiles-energy-sankey` | `title`、`balancer_label` |

> 可视化卡片编辑器只能存普通字符串，所以映射在那里显示为**空字段**，标签会写
> `accepts an en/zh map`。这些参数请在 YAML 编辑器（⋮ → *在 YAML 中编辑*）里改。

> Home Assistant 自带的卡片（`markdown`）以及视图 / 页签标题属于 HA 本身、不属于本集成，
> 它们的文字无法跟随语言。请把这些写成语言无关的内容，或者为它们统一选一种语言。

### 为什么视图页签无法跟随语言

HA 从 `view.title` 取页签文字，**完全没有本地化环节**：

```js
// home-assistant/frontend - src/data/lovelace/config/view.ts
computeViewTitle = (view, index) => view.title ?? (view.path ? titleCase(view.path) : String(index));
```

对比 HA 内置的能源面板：它是靠 **strategy** 生成视图、在 JS 里调
`hass.localize(...)` 才让页签跟着语言的。代价是整个视图都由 JS 生成，
只为了一行标签把仪表盘绑上去并不划算。

由此有两件很容易踩错的事：

1. **`view.title` 是固定字符串**，没有按用户变化的语言，工具栏切换时客户端也
   无法改写它 —— 所以本集成生成的仪表盘把三个页签固定为英文
   （`System`、`Device`、`Control`）。想让两种语言的用户都看得对，就自己写成双语
   —— 例如 `System status / 系统状态`；或者改用视图内部的语言无关标题
   （emoji + 设备 SN）。
2. **写了 `icon` 就会把标题藏掉**。除非显式要求两者都要，否则 HA 只渲染图标**或**标题：

   ```js
   const icon_and_title = view.show_icon_and_title && view.icon && view.title;
   const icon_only = view.icon && !icon_and_title;
   ```

   所以「有 `icon` 但没有 `show_icon_and_title: true`」的视图**只显示图标**，
   标题只残留在悬停提示里。想同时看到图标和文字就得加这个开关。

## 1. `custom:hoymiles-power-flow`

把系统画成一张**接线示意图**（和手机 App 的系统页一致）：每条支路一个图标、
中间是主机（App 那套「方框里插头」的图）、并网点用一个小圆点，连线是粗圆头线，
上面有一道顺着能量方向流动的光流。节点图标直接用 App 的那套图（内嵌在卡片里）。

- **中间的主机只要系统里有任何一路在动就用彩色图**，全系统都 0 W 时才用暗色图。

```
⬜ 光伏1 ──┐                       ┌── ⬜ 光伏2
           ├── ▣ 逆变器 ─── ● ── ── ⬜ 电网
⬜ 微储   ──┘                       └── ⬜ 灯泡
                                     └── ⬜ 智能插座
```

```yaml
type: custom:hoymiles-power-flow
dev_id: MSA-280520260806
title: 我的家
language: zh
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dev_id` | string | — | **必填** |
| `title` | string | 本地化的「我的家」 | 标题文字 |
| `show_title` | bool | `true` | `false` 隐藏标题与设备 SN，只留右侧信号图标 |
| `language` | `en` \| `zh` \| `de` | *工具栏切换* | 钉死本卡片语言；不填则跟随工具栏里的选择（默认英文）。`zh-Hans` / `zh-Hant` / `zh-CN` 都选中文，`de-AT` / `de-CH` 选德语。 |
| `temperature_entity` | entity id | — | 标题右侧显示的温度实体 |
| `show_rssi` | bool | `true` | 右上角 Wi-Fi 信号扇形 |
| `gradient` | bool | `true` | 是否画接线图下的**纯白底**。`false` 则不画，露出卡片自身底色――此时请配浅色主题，因为示意图的文字颜色是固定的 |
| `max_width` | number (px) | `620` | 插图最大宽度，超宽时保持居中 |
| `flow_speed` | number | `1` | 光流速度倍数，`0.5` 更慢、`2` 更快 |
| `entities` | map | — | 实体覆盖，键为后缀（见下） |

### 数据来源

全部来自普通实体状态，**不依赖 recorder**；每条支路都直接取秒级 `quick/state`
的系统实体，与 App 系统页同源：

| 节点 | 实体后缀（`sensor.<dev>_…`） |
|---|---|
| 光伏1（左上） | `sys_pv_p` |
| 光伏2（右上） | `sys_pv2_p` |
| 电网（右） | `sys_grid_p`（正 = 受电） |
| 灯泡（右下） | `sys_load_p` |
| 智能插座（右下，灯泡下方） | `sys_sp_p` |
| 微储（左下） | `sys_bat_p`（负 = 充电），缺失时回退 `bat_p`；SOC 取 `sys_soc` |
| 状态 | `battery_status`（`standby` / `charge` / `discharge` / `lock`） |
| 信号扇形 | `rssi`（dBm） |

### 行为说明

- **有功率（`|P| ≥ 5 W`）的支路用彩色图标，没功率的用同款暗色图标**，
  这就是 App 表达「这里没数据」的方式，不用去读数字。
- 实体**不存在**的支路（从机没有系统级读数）连节点和连线一起省略。
- 电网标题随流向变化：取电显示 `电网输入`、馈网显示 `电网输出`、约 0 W 时
  只写 `电网`——不假装知道方向。
- 连线本身保持灰色不变。支路功率 **≥ 5 W** 时，线上会有**一条**光流从一端发送到另
  一端：白色的头部，后面跟着一条逐渐淡出的尾巴。全程只有**一条**——用重复的花纹
  会在长线上同时出现两条三条，看起来像装饰而不像“有东西被送过去”。
- 光流**永远顺着能量流动的方向**：从光伏1 / 光伏2 流出、从放电的微储流出、从取电的
  电网流入、流入充电的微储、逆变器送电时从逆变器流向汇流点、电网或光伏2 给电池
  充电时倒流回逆变器，以及流入灯泡 / 智能插座。光流颜色随支路变化，速度随功率加快。
- **画面上不画方向箭头**：哪边进哪边出一律由光流表示（箭头只是同一件事的第二份
  更粗糙的说明，已按要求去掉）。
- 走完时间**按路径长度算**，所以短线与长线速度一致（一趟大约 1~4 s），走到底后
  从起点重新发射。觉得还快/还慢就用 `flow_speed` 整体调。
- 光流是 **CSS 动画**，不靠脚本定时器：卡片被切到后台、或者切换仪表盘页签再切
  回来，它都照跑到原来位置，不会再停住。读数变化时重画整张图，也会接着刚才
  走过的距离继续。
- **右上角是 RSSI 信号图标**（与「电池卡片」及 App 的 Wi-Fi 图标同款）：
  四根高度递增的信号条，点亮的条数（0~4）表示信号质量，旁边直接跟 `-21 dBm`
  读数，悬停可看说明：

  | RSSI | 点亮条数 |
  |---|---|
  | ≥ −55 dBm | 4（优秀） |
  | ≥ −65 dBm | 3（良好） |
  | ≥ −75 dBm | 2（一般） |
  | < −75 dBm | 1（较弱） |

  设备不上报 `rssi` 时自动隐藏，不需要可以把 `show_rssi` 设为 `false`。
- 单独覆盖某个实体用 `entities:` 段：

  ```yaml
  entities:
    system_pv_power: sensor.my_pv_power
    system_battery_power: sensor.my_battery_power
    system_grid_power: sensor.my_grid_power
    system_load_power: sensor.my_load_power
    system_smart_plug_power: sensor.my_system_smart_plug_power
    soc: sensor.my_soc
    battery_status: sensor.my_battery_status
    rssi: sensor.my_rssi
  ```

### 符号约定

`sys_grid_p` **受电为正**，微储功率**充电为负**；卡片在绘制前统一成能直接
理解的语义。没有功率流动的节点只是灰环，不会挂「待机」标签。

## 2. `custom:hoymiles-battery`

按**实际电池包数量**自适应绘制电池堆：1～4 个电池包各对应一种外形，每个模组
配一个左右交替的气泡显示自己的 SOC 与温度（和 App 的 HiBattery X 页面一致）。
插图按**产品图**绘制：整体一块机身加自顶向下由浅到深的单一渐变、模组之间细缝分隔、
品牌圆标放在第一个模组上；顶部深色头模组画的是**显示条**——电源符号、
「000 W / SOLAR」、两个尖括号夹住的 SOC、「000 W / BATTERY」
（真机显示条上那组小状态图标与 Wi-Fi / 循环符号不上看板，已省略）。
整机画成一个干净矩形：没有侧板，也没有脚。

  - SOLAR / BATTERY 显示的是**本机**的 `pv_power` / `bat_power`（面板画的是设备自身），
    四个角的气泡仍用系统级读数。数值按实际显示（**不补零**），最大到四位（9999 W）。
  - **两个尖括号就是充放电指示**：充电时画左箭头、放电时画右箭头，都是白色；电池待机时两个都不画。
    充电对应电池功率为负，与固件约定一致。

主机温度的气泡也指向这个头模组。

插图画面的四个角落分别是光伏、并网口、电池、离网口。它们的图标都是**直接画出来的**，不是贴 emoji：
光伏是**琥珀色太阳，八道圆头光芒**，这样它和卡上那些单色扁平的状态图标属于同一套；
并网口保留原来的「插座面板 + 插头」画法，只是画得更大（36 个 viewBox 单位，太阳是 28）——
面板、插头本体和插脚在这个尺寸下才分得开。

```yaml
type: custom:hoymiles-battery
dev_id: MSA-280520260806
title: HiBattery 4020 X
language: zh
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dev_id` | string | — | **必填** |
| `title` | string | 自动读设备型号 | 覆盖设备注册表里的型号 |
| `show_title` | bool | `true` | `false` 隐藏标题 |
| `language` | `en` \| `zh` \| `de` | *工具栏切换* | 钉死本卡片语言；不填则跟随工具栏里的选择（默认英文）。`zh-Hans` / `zh-Hant` / `zh-CN` 都选中文，`de-AT` / `de-CH` 选德语。 |
| `show_history` | bool | `true` | 可选历史数据区（需启用 recorder） |
| `show_host_temp` | bool | `true` | `false` 隐藏主机温度 |
| `max_width` | number (px) | `560` | 插图最大宽度 |
| `alarm_entity` | entity id | — | 该实体为 `on` 时标题左侧显示铃铛 |
| `entities` | map | — | 实体覆盖（见下表） |

| `entities` 键 | 含义 |
|---|---|
| `pack_count` | 电池包数量 |
| `pv` | 光伏功率 |
| `grid_on` | 并网口功率 |
| `grid_off` | 离网口功率 |
| `battery` | 电池功率 |
| `battery_status` | 电池状态 |
| `soc` | 系统 SOC |
| `pack<N>_soc` | 逐包 SOC |
| `pack<N>_temperature` | 逐包温度 |
| `battery_temperature` | 固件自己算的电池温度（主机温度的兵底） |

### 行为说明

- **标题默认取设备注册表里的型号**（本机实测为 `HiBattery 4020 X`，来源于固件 MQTT
  discovery 的 `device.model`），所以换机型不用改卡片配置；显式写 `title` 则覆盖它。
- 电池数量优先取 `pack_count`（`device/state` 的 `pack_num`），缺失时按实际能读到
  SOC 的 `pack1_soc`…`pack4_soc` 推断，上限 4（与固件 `packs` 截断一致）。
- 逐包数据用 `pack<i>_soc` / `pack<i>_temperature`；四周功率用 `pv_power`、
  `grid_on_power`、`grid_off_power`、`battery_power`。
- **主机温度取已安装电池包的平均值**，画成一个与逐包气泡同款的独立气泡（标注为
  「主机」，样式与 Battery 1/2/3 完全一致）——头部本身没有温度传感器，厂商 App 用的
  也是这个口径。读不到温度的包不参与平均；一个都读不到时回退到固件的
  `battery_temperature`（`bat_temp`）。`show_host_temp: false` 可去掉该气泡。
- 标题右侧的信号格数由 `rssi`（dBm）换算。
- 历史数据区（可选）通过 `recorder/statistics_during_period` 读取长期统计，画 SOC
  曲线并汇总该区间的充电 / 放电电量；recorder 未启用时只提示、不影响其余部分。

## 3. `custom:hoymiles-pack-list`

电池堆插图的紧凑替代：一行一个电池包，左侧 SOC 进度条、右侧 SOC 百分比与加热标记。
包数量与电池卡片用同一套规则。

```yaml
type: custom:hoymiles-pack-list
dev_id: MSA-280520260806
language: zh
title: 电池电量
columns: 2
show_temperature: false
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dev_id` | string | — | **必填** |
| `title` | string | 本地化的「电池电量」 | 标题文字 |
| `language` | `en` \| `zh` \| `de` | *工具栏切换* | 钉死本卡片语言；不填则跟随工具栏里的选择（默认英文）。`zh-Hans` / `zh-Hant` / `zh-CN` 都选中文，`de-AT` / `de-CH` 选德语。 |
| `columns` | number | `1` | 按 N 列排布；不填为单列 |
| `show_temperature` | bool | `true` | `false` 时只显示 SOC，不显示 ℃ |

## 4. `custom:hoymiles-history-chart`

按**日 / 月 / 年**查看曲线，并可用 `‹` `›` 或日期输入框翻到任意时间段，绘制风格与
厂商 App 的历史页一致。功率 / 电量这类**会相加**的 series 会堆叠（正值向上、负值向下，
因此「充电 / 放电」双极性传感器自然分居 0 线两侧）；而 SOC、温度这类**水平量**默认
**叠加显示**——三个电池包都是 81% 时若堆叠，第二条曲线会被画到 81~162%、第三条到
162~243%，在 0~100 的轴上就只有第一条看得见。用 `stack` 可显式指定。

```yaml
type: custom:hoymiles-history-chart
```

### 行为说明

- 数据来自 `recorder/statistics_during_period`（长期统计），**无需管理员权限**，
  也不接触数据库文件。
- 顶栏与厂商 App 的历史页一致：**左上角是日期胶囊（圆形 `‹` `›` 包着日期），
  右上角是范围下拉（日 / 月 / 年）**；曲线下方的图例也是 App 那种圆角胶囊。
- 纵轴刻度会按实际步长自动决定小数位（例如 1.25 kW 的步长会显示 `1.25` 而不是取整成 `1`）。
- 纵轴与悬停浮窗**永远使用同一单位**。前缀只在 **10 k** 以上启用：88 W 显示为
  `88 W` 而不是 `0.09 kW`——旧的 1.5 kW 阈值相当于 100 W 分辨率，会把最该看的波动抹平。
- **纵轴会自动适配当前屏幕上的数据**：范围由可见分桶里的真实峰值算出来并向上取整，
  空闲的 90 W 夜晚会铺满整张图，而不是被压在 ±2500 W 量程下压成一条线。缩放时
  也会重新适配——这才是放大后能看清细节的原因。想固定量程时填 `span` / `min` / `max`，
  可让不同日子之间保持同一刻度便于横向对比。整段都是 0 时会退回整个周期的峰值，
  轴不会被压成 ±1 W。
- **「向上取整」用的是一套细阶梯，不是 1 / 2 / 5 / 10。** 粗阶梯最多会浪费 5 倍量程：
  某天最低到 2.2 kW，却给了 ±5 kW 的轴，曲线被压到底部五分之一，看起来像「什么都没发生」。
  现在用 `1, 1.25, 1.5, 2, 2.5, 3, 4, 5, 6, 8, 10 × 10^n`，最多只浪费约 1.33 倍，
  而每一档仍然是 125 的倍数，五个标签（`max`、`max/2`、`0`、`-max/2`、`-max`）
  最多两位小数即可精确表示。例如峰值 2 154 W 现在给 ±2 500 W，标签是
  `2500 / 1250 / 0 / -1250 / -2500`，不再是 ±5 000 W。
- **堆叠只用于「构成一个总量」的曲线，不用于彼此独立的读数。** 三个都是 88 W 的读数
  画成堆叠后，第二条会落在 88..176 W、第三条 176..264 W，于是**数值完全相同**的曲线
  反而一上一下错开，轴顶还变成一个没人要的合计值。`光伏功率` / `电池` / `电网与负载`
  是三个独立测量，所以内置功率图用 `stack: false`。堆叠仍然适合合计本身就有意义的地方：
  各光伏端口（合起来才是整串组件）与分相功率。
- **水平量也绝不能堆叠**：三个 81 % 的电池包会画在 0..81 %、81..162 %、162..243 %，
  在 0..100 的轴上只剩第一条可见。`symmetric: false`（SOC / 温度轴）因此默认叠加显示；
  `stack: true` / `false` 可显式覆盖。
- **图例是一组开关。** 点某个胶囊只隐藏那一条曲线，其余保持原样——关掉 `光伏功率`，
  `电池` 与 `电网与负载` 仍然画着；再点一次就恢复。被关掉的曲线是从图中移除（不只是变淡），
  也不再出现在悬停浮窗里；剩下的曲线会从零线重新堆叠，不会悬在一条它已不再接触的轴上。
  对应的胶囊会变成该颜色的空心圆环并变淡，所以“关闭”和“在画”一眼可分。
  **曲线样式从不因筛选而改变**：颜色、线宽、填充透明度都和不筛选时完全一致，
  所以数值相同的曲线在两种状态下看起来一样。全部关掉后只留坐标轴与网格（空图），
  点一下图表区域即可全部恢复。
- **面积会混色，线条不会。** 先画所有面积，所以两条数值相同的曲线会在重叠处混出中间色
  （绿叠蓝 → 青），这正是厂商 App 里重叠区的表现。之后按 `series` 顺序逐条画线条，
  后画的盖住先画的：`光伏功率` → `电池` → `电网与负载`，所以重叠处看到的是蓝色。
- **整段都会画线，包括值为 0 的平段。** 停在 0 W 也是数值，会沿零轴画出一条线，而不是消失。
  （之前「按带有无高度来断笔」正是把平坦时段留白、并在边缘留下孤立小圆点的原因。）
- **整块数值都为 0 时也会画出基线。** 四个光伏口一整天都没发电就是四条平线，而堆叠图没有带高
  可描——所以就直接把基线按各系列颜色画出来，而不是留一个看起来像「图表坏了」的空框。
- **滚轮可以横向缩放时间轴**：以鼠标位置为锚点放大/缩小（光标下的时刻保持
  不动），按住拖动可以左右平移，双击还原整个时间段。缩放中右上角会出现
  *已放大 / 还原* 徽标。**不会重新拉数据**——卡片本来就持有整个时间段，
  只是画其中一段，所以缩放是瞬时的；y 轴会跟着可见区间重新适配，放大才真正
  看得到细节。`zoom: false` 可关闭该手势。
- **鼠标移到图上时，同一 `sync_group` 的其它图表会在同一时间点显示引导线和浮窗**
  （如仪表盘的「历史数据」驱动「电池容量(SOC)」）；移开后一并消失。匹配按
  时间戳进行，所以两张图即使分桶粒度或数据缺口不同也能对上。
- `show_toolbar: false` 配合 `sync_group` 就能做成「上面一张图控制、下面几张图只跟随」
  的仪表盘。
- 卡片被移除时会自动从组里注销，不会残留。

### 曲线命名，以及将来拆开电网与负载

曲线名称**不带 `[+]/[-]` 后缀**。带符号的功率曲线本身就说明了能量流向（正=出，
负=入），数值就是大小，所以内置图表直接叫 `电池` / `电网与负载`。原来的长名字
（`电网&负载 输出[+]/输入[-]`）比图例还宽，在悬停浮窗里会被截断。

没装电表时，固件只上报**一个** `grid_on_power`，它就是电网 **与** 负载的合成值，
事后无法拆开。等电表的 MQTT 主题加入后，两者是两个独立测量，图表就变成四条曲线，
**只需要改 `series` 列表**：

```yaml
series:
  - entity: sensor.x_pv_power          # 黄
    name: 光伏功率
    color: "#f59e0b"
  - entity: sensor.x_bat_power         # 绿
    name: 电池
    color: "#22c55e"
  - entity: sensor.x_grid_power        # 蓝
    name: 电网
    color: "#3b82f6"
  - entity: sensor.x_load_power        # 玫红：第四个色相，与前三者距离都远
    name: 负载
    color: "#db2777"
```

注意语义：带符号的 `电网`（外送为负、购电为正）与始终为正的 `负载` **并不能**
相加成原来那条合成曲线，所以不要把它们堆叠在一起——要么用 `symmetric: false`
分到两个 pane，要么就当两条独立曲线看。拆开只是**数据**变化，卡片本身不假定
曲线条数。

## 5. `custom:hoymiles-gauge`

一张**统计卡**：左上标题、右上图标、中间大字数值，下方**一条绿弧**按数值占
`min`~`max` 的百分比填充，弧中央同时显示该百分比。HA 自带 `gauge` 卡片的轻量替代。

```yaml
type: custom:hoymiles-gauge
entity: sensor.msa_280520260806_battery_charge_energy_today
name: 今日充电量
unit: kWh
scale: 0.001
max: 10
min: 0
decimals: 2
icon: ⚡
label: 自发自用率
color: "#22c55e"
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `entity` | entity id | — | **必填**，驱动大字数值 |
| `name` | string | 实体名 | 标题 |
| `unit` | string | 实体单位 | 显示单位 |
| `scale` | number | `1` | 显示前的换算系数（`0.001` 可把 Wh 显示成 kWh） |
| `max` | number | — | **显示单位下的**上限；不填表示弧线随数值增长 |
| `min` | number | `0` | 下限 |
| `decimals` | number | `2` | 数值小数位 |
| `icon` | string | — | 可以是**内置图标名**（见下文），也可以是任意文字 / emoji，后者直接当文字画出来 |
| `label` | string | — | 百分比下方的说明文字 |
| `color` | CSS 颜色 | `#22c55e` | 弧线颜色 |
| `show_arc` | bool | `true` | `false` 时去掉弧线与百分比，只剩读数 |

### 比例模式

当真正关心的数字是**两个实体之间的比例**（而不是占某个虚构上限的百分比）时，
可以单独给弧线指定数据源。大字读数仍取 `entity`，只有弧线与百分比来自比例。

| 参数 | 说明 |
|---|---|
| `percent_numerator` | 比例模式必填 |
| `percent_subtract` | 可选，从被减数中扣除 |
| `percent_denominator` | 可选，默认等于被减数 |

```yaml
type: custom:hoymiles-gauge
entity: sensor.msa_280520260806_system_pv_energy_today
name: 今日发电量
unit: kWh
scale: 0.001
icon: panel
label: 自发自用率
percent_numerator: sensor.msa_280520260806_system_pv_energy_today
percent_subtract: sensor.msa_280520260806_grid_on_energy_out_total
percent_denominator: sensor.msa_280520260806_system_pv_energy_today
```

即：自发自用率 = （发电量 − 上网电量）÷ 发电量。

### 内置图标

`icon` 也可以填下列名字，而不是 emoji。每个图形都是**单色 SVG + 一层浅色圆形底**，
三张汇总卡因此拥有同一个轮廓，同时各自说明自己在统计什么。
其他字符串（包括 emoji）仍按文字渲染，旧配置不会失效。

| 名称 | 长什么样 | 适合的含义 |
|---|---|---|
| `panel` | 琥珀色四格光伏板 + 支架，淡黄圆底 | 今日发电量（默认） |
| `sun` | 八道光芒的琥珀色太阳 | 发电量，更抽象的说法 |
| `cycle` | **两个**蓝色箭头围着一个实心圆点，淡蓝圆底 | 今日**放电**量（默认） |
| `battery` | 绿色电池 + 电极头 + 闪电，淡绿圆底 | 今日**充电**量（默认） |
| `dot` | 中性实心圆 | 兜底 |

`batOut` / `batIn` 保留为 `cycle` / `battery` 的别名：改版前生成的仪表盘
不需要重新生成就能拿到新外观。

`cycle` 刻意用**两个**弧、每个带一个箭头，而不是一个环加一个箭头：
单箭头看起来像「刷新」，两个箭头才是「能量绕一圈又回来」。
两段弧对称（各 156°、间隔 12°），整条弧是一笔描边，所以缩到 22 px 也不会糊。

圆底用的是 `rgba(..., .16)` 而不是固定浅色，所以同一张卡片在白色卡片和深色主题下
都成立——写死的 `#fef3c7` 在切换深色主题后会变成一块发光的盘子。

```yaml
# 换一个图标就是一个词的修改
icon: panel      # 或 sun
icon: cycle
icon: battery
```

### 行为说明

- 百分比 = `(值 − min) / (max − min) × 100`，四舍五入到整数；值超出量程时钳到 0~100%。
- 实体还没上报数据时仍画出空弧，数值与百分比显示 `—`，卡片不会变成一片空白。
- 把 `max` 设为 100 并直接接 SOC 传感器，就是一张电池电量表。

## 6. `custom:hoymiles-control`

把《禾迈微储 MQTT 协议开发指南》§10~§20 里**所有可下发的控制**做成按钮 / 输入框。
指令**直接发布到协议 topic**（qos 1、retain false），因此即使某个 discovery 实体缺失
或选项列表比协议窄，卡片也仍可用；当前值则从对应实体回读。

```yaml
type: custom:hoymiles-control
dev_id: MSA-280520260806
language: zh
title: 设备控制
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dev_id` | string | — | **必填** |
| `title` | string | 本地化的「设备控制」 | 卡片标题 |
| `language` | `en` \| `zh` \| `de` | *工具栏切换* | 钉死本卡片语言；不填则跟随工具栏里的选择（默认英文）。`zh-Hans` / `zh-Hant` / `zh-CN` 都选中文，`de-AT` / `de-CH` 选德语。 |
| `show_power_ctrl` | bool | `true` | `false` 隐藏「目标功率」行 |
| `show_phase` | bool | `true` | `false` 隐藏「分相输出上限」行 |
| `show_log` | bool | `true` | `false` 隐藏「MQTT 日志」行（日志本身默认是关的） |
| `show_topics` | bool | `false` | 在每行下方显示 MQTT 主题（调试用） |
| `subtitle` | bool | `true` | `false` 隐藏标题右侧的灰色说明 |

### 各行与协议 topic

| 行 | 协议 topic | 说明 |
|---|---|---|
| 设备开关 | `switch/<dev_id>/set` | `ON` / `OFF` |
| EMS 模式 | `select/<dev_id>/ems_mode/command` | `general` / `mqtt_ctrl` / `tou_plan`，不支持的选项自动置灰 |
| 目标功率 | `number/<dev_id>/power_ctrl/set` | 带符号设定点：**正数放电，负数充电**。仅 `mqtt_ctrl` 模式有效，需至少每分钟下发一次，否则设备回落到自行控制 |
| 最大输出 | `number/<dev_id>/output_power/set` | 输出上限（W）。只改上限，不影响当前功率 |
| 分相输出上限 | `number/<dev_id>/phase_output_power/set` | 每相（A / B / C）上限，按 `{"phase_a":..,"phase_b":..,"phase_c":..}` 下发 |
| 获取 TOU 计划 | `sensor/<dev_id>/tou_plan/get` | 应答发布在 `tou_plan/status` |
| 重启设备 | `button/<dev_id>/reboot/trigger` | 二次确认后发 `RESTART` |
| MQTT 日志 | （不发送，只是订阅） | 默认关闭；打开后实时显示设备上报与 HA 下发的数据 |

### 设定点定时重发在 Home Assistant 里跑

`power_ctrl` 是**租约，不是设置**：固件只在报文持续到达时保留该值，最后一次下发约一分钟后
就回落到自行调控。所以「下发」旁边的 **每隔 N 秒** 开关并**不**在浏览器里跑定时器，
而是调用集成服务：

| 服务 | 作用 |
|---|---|
| `hoymiles.set_power_ctrl` | 立刻下发一次 `value`，之后每 `interval` 秒重发一次 |
| `hoymiles.stop_power_ctrl` | 停止重发，设备约一分钟后回落 |
| `hoymiles.get_power_ctrl` | 返回 `{active, value, interval, next_in}`（有返回值，模板和卡片都能读） |

为什么必须这样做：卡片里的 `setTimeout` 会随着卡片一起消失，而 Lovelace 每次切换页面都会
销毁该页的元素。以前离开控制页，重发就悄悄停了，屏幕上的开关却还显示「开」——其实设备早就
回落了。定时器放到 Home Assistant 里，切页面、关浏览器、后台标签页被节流都不影响，而且所有
客户端看到的是同一份状态。

两点注意：

- Home Assistant 重启后重发**不会自动恢复**。此时设备本来也已经丢掉了设定值，所以卡片回来
  时开关是关着的，而不是悄悄再去指挥硬件。
- 关闭开关会先确认，并且是**真的**停掉服务端任务——设备被释放，而不是被压在一个没人看得见的
  设定值上。
- **一旦离开 `mqtt_ctrl`，重发立即停止。** 设定点只在 MQTT 控制下有意义，`general` / `tou_plan`
  两种模式下功率由设备自己决定，所以模式一变任务就取消——不管是卡片上点的、
  `hoymiles.set_ems_mode` 下发的、自动化触发的，还是设备自己超时回落的。切回来时是**空白草稿**：
  0 W、默认间隔、开关就绪，而不是上一次的设定值。


### MQTT 日志

「计划与维护」最后一行是 **MQTT 日志**，**默认关闭**。打开后卡片会通过 Home Assistant 的
WebSocket（`mqtt/subscribe` 命令）订阅两个通配主题，把两个方向的数据混在一条时间线上显示：

| 通配主题 | 内容 |
|---|---|
| `homeassistant/+/<dev_id>/#` | 设备上报的状态（`quick/state` 1 秒、`device/state`、`system/state`、`tou_plan/status`、discovery 配置）+ HA 下发的命令（`set`/`command`/`trigger`/`get`） |
| `hoymiles/<dev_id>/#` | 集成自己的主题（`availability` 在线看护、`ems_mode/state` 回显） |

- 方向按主题判定：**HA 写命令侧**（`/set`、`/command`、`/trigger`、`/get`）记作
  「HA 下发」，其余记作「设备上报」；`hoymiles/` 那一族是集成自己的，也算下发。
- 每行显示时间、方向胶囊、去掉样板后的主题（如 `sensor/quick/state`，完整 topic 在悬停提示里）
  和 payload；payload 是 JSON 就自动缩进，过长则截断。
- 列表**只保留最近 200 条**（`quick/state` 每秒一条，约 3 分钟），丢弃的旧条数会计数显示。
- 关闭时**不订阅任何主题**（不看就不占资源）；离开页面会退订，回到页面时若还开着会自动恢复。
- 🔴 `mqtt/subscribe` 在 Home Assistant 里**仅管理员可用**，所以非管理员账号打开时会看到
  一行提示而不是数据流。

### 行为说明

- 卡片的范围提示（如 `-1000 ~ 1000 W`）优先读实体的 `min` / `max` 属性，
  读不到时用协议默认值。
- 布局参考 iOS 设置页：小组件包在圆角分组里、组间有灰色小节标题
  （**电源与模式 / 功率设置 / 计划与维护**）、每行是「图标 + 名称 + 右侧控件」，
  分割线**左侧内缩**；开关机与 EMS 模式用**分段控件**，危险操作（重启）用红色。
- **开关机很慢**：固件要把 PCS（及电池包）真正停下来或启动起来。卡片会把请求状态
  显示为「待确认」最多 5 秒，直到设备回读到位，随后短暂显示对勾。
- 每行的 MQTT topic **默认不显示**（它们是调试信息，会挤掉正文）；需要时用
  `show_topics: true` 打开。
- **MQTT 日志**：见上一节。它默认关闭，开关就在「计划与维护」那一行；`show_log: false`
  可以把整行去掉。

## 7. `custom:hoymiles-tou-editor`

分时计划可视化编辑器。它通过集成服务（`hoymiles.set_tou_day_plan`、
`set_tou_week_plan`、`get_tou_plan`、`set_ems_mode`）与设备交互；万一集成不在了，
会退化为直接 `mqtt.publish`。

```yaml
type: custom:hoymiles-tou-editor
dev_id: MSA-280520260806
language: zh
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dev_id` | string | — | **必填** |
| `title` | string | 本地化的标题 | 卡片标题 |
| `language` | `en` \| `zh` \| `de` | *工具栏切换* | 钉死本卡片语言；不填则跟随工具栏里的选择（默认英文）。`zh-Hans` / `zh-Hant` / `zh-CN` 都选中文，`de-AT` / `de-CH` 选德语。 |
| `require_tou_mode` | bool | `true` | 只有在 EMS 模式为 `tou_plan` 时才渲染编辑界面；`false` 关掉该门控 |
| `ems_entity` | entity id | 自动 | 覆盖用于读取 EMS 模式的实体 |
| `status_entity` | entity id | 自动 | 覆盖用于读取计划状态的实体 |
| `day_ack_entity` | entity id | 自动 | 覆盖日计划应答实体 |
| `week_ack_entity` | entity id | 自动 | 覆盖周计划应答实体 |

### 两级模型：日计划 + 周计划（务必先理解这个）

TOU 在设备里是**两层数据**，缺一层都不会运行：

```
日计划 day1..day8   若干时间段，例如「09:00-11:00 强制充电 400W」
        ↑ 被引用
周计划 Mon..Sun     每个星期指向 day1..day8 中的哪一个
```

**只写日计划而没有周计划 → 设备保存了但永远不会执行。** 这是最常见的「下发了却没运行」
的原因：周计划表全空时看起来像「已经配好了」，用户改完日计划保存后发现设备毫无反应。
因此卡片**不会把空表当作事实**：它只显示自己真正知道的内容，映射关系没弄清楚时不会下发。

### 正确设置步骤

1. **点「读取」**。读取是显式动作：它会把屏幕上的内容整体换成设备里的内容，所以打开卡片
   不会在你背后偷偷执行。已经配过的设备会逐个回答 7 个星期；完全没配过的设备只回一次
   `tou plan not configured`，卡片就停下来不再往下问。
2. **编辑日计划**：点选 `day1`..`day8` 中的某个标签页，用「+ 添加时段」增加时间段。
   | 字段 | 含义 |
   |---|---|
   | Mode | `Force charge` 强制充电 / `PV charge` 只吃光伏 / `Discharge` 自发自用(允许放电) |
   | Start / End | 时间段，15 分钟粒度 |
   | sh% / sl% | 充电截止 SOC / 放电截止 SOC |
   | pc W | 充电功率上限 |
   | pd W | 放电功率上限 |
3. **填写周计划**：在「Week plan」表里给每个星期选一个 `dayN`。下拉框会标注每个
   日计划有几段、还是空的（`day2 · empty` 这种选不上去的会被拒绝）。
4. 点 **「保存并激活」**。卡片会自动按正确顺序下发：

   ```
   切到 tou_plan  →  day1..day8  →  周计划  →  回读当天计划校验
   ```

   > 顺序不能反。固件的 `HmMqttIsTouConfigReady()` 要求 EMS **已经**在 `tou_plan`
   > 才接受计划，否则日计划回 `ack 10`、周计划回 `ack 6`，两者都直接丢弃。

5. 下发过程中会弹出一个**进度弹窗**，页面变灰，逐步显示：
   `检查计划` → `切换 EMS` → `下发日计划 (n)` → `下发周计划` → `回读校验`。
   成功后会显示绿勾「已保存并校验通过」并**自动关闭**；
   失败或超时则显示红叹号、具体原因与一个「关闭」按钮，**弹窗不会自动消失**。

   > 「读取」走同一个弹窗，7 个星期逐个显示，已读过的会变成
   > `Mon → day1 · 2 segments`。每个星期 2–5 秒；如果设备上根本没有计划，
   > 大约 1 秒就结束——第一次拒绝已经说明整台设备是空的，没必要再问六次。

   > 一次完整保存（7 天日计划 + 周计划 + 回读校验）大约需要 **50 秒**，因为
   > 设备每次回读要 2–5 秒。

### 三种读取状态，对应三种下一步

表格上方那条提示是**纯文字**：只说明「卡片到底知道多少」，不再重复上方已经有的两个按钮。

| 状态 | 含义 | 可以做什么 |
|---|---|---|
| `尚未从设备读取` | 还没问过设备 | 点「读取」，或直接在下面排表 |
| `设备上还没有计划` | 设备明确回复了 `tou plan not configured`，确实没有任何计划 | 直接排表，点「下发」 |
| `已从设备读取` | 7 个星期全部有应答 | 改完直接下发 |

**一旦真的编辑了时段**，状态就会变成「新计划——将覆盖设备内容」，下发自动解锁——
排表这个动作本身就是「我要覆盖」的决定，不需要再点一个额外按钮。
但**一张没人动过的空表仍然不允许下发**，因为那会静默清掉一张你看不见的计划。
**只读回一部分**（有的星期应答了、有的没有）**不能**靠编辑绕过：必须重新读一次，
否则那些没应答的星期会被取消映射。

### 未保存的修改会被保护

改了任何东西但还没保存时，按钮旁边会出现 `unsaved changes` 标记；此时点
「从设备重新载入」会变成「Discard & reload」，再点一次才会真的用设备内容
覆盖你的草稿。这样不会因为随手点一下而把刚编好的计划冲掉。

### 时间段的串联与 24:00

- 开始/结束都是**下拉选择**，不是手输。开始时间的候选项从「上一段结束」开始，
  结束时间的候选项从「本段开始 + 15 分钟」开始，到 `24:00` 结束。
- 选择开始时间时仍可往后选（留出空档），但**不可能选到上一段内部**，所以永远不会撞上
  ack 3（重叠）；结束时间也不可能不晚于开始，所以永远不会撞上 ack 9。
- `24:00` 是结束专用的标签。它相当于固件的槽位 `96`，**不会**再被显示成 `00:00` ——
  这正是旧版本「存 96、显示 00:00、再存变 0、ack 9」的根源。
- 删除中间某一段时，后面的段保留自己的时间（会留出空档，这是合法的），
  不会被静默改写。

### 时间段之外会怎样

不在任何时间段内时，设备回落到**自发自用**（`work_mode=2`）；进入时间段后按该段的
`mode` 运行（`work_mode=3`）。所以一个只覆盖 09:00-11:00 的日计划，其余 22 小时都是
自发自用，这是正常的。

### 结束时间写 00:00 = 午夜（24:00）

**此节描述的旧行为已被上节的 `24:00` 下拉选择取代。** 现在结束时间直接选 `24:00`，
不再有「填 00:00 代表午夜」的歧义。

> 早期版本在这里有 bug：设备存的是 `te=96`，卡片用原生时间控件显示成 `00:00`，再保存
> 一次就变成了 `te=0`，于是被设备拒绝并返回 **day ack 9**。现已彻底改掉。

### 固件对日计划的硬性校验

卡片现在会在**下发之前**先按同样的规则做本地校验，直接标出是 `dayN 第几段`、
具体错在哪，不再把数据发出去换一个原始错误码回来：

| 规则 | 违反时的 ack |
|---|---|
| 每段 `ts < te`（结束必须晚于开始） | `9` |
| `ts`、`te` 在 `0..96` 内 | `5` |
| 同一天内的时间段不能重叠 | `3` |
| 每份日计划最多 12 段 | `2` |
| 充电段（mode 1/2）`sh` 在 10..100 | `6` |
| 放电段（mode 4）`sl` 在 10..100 | `6` |
| `pc`/`pd` 不超过 `微储台数 × 2500 W` | `7` |

### ack 码对照表

底部 Status 里的 `day ack` / `week ack` 现在会直接显示成「码 · 说明」，例如
`day ack: 9 · end must be later than start`。

| day ack | 含义 | week ack | 含义 |
|---|---|---|---|
| 0 | 成功 | 0 | 成功 |
| 1 | 通用错误 | 1 | 通用错误 |
| 2 | 时段过多（最多 12 段） | 2 | 星期名称无效 |
| 3 | 时间段重叠 | 3 | 同一个星期被重复映射 |
| 4 | 模式超出范围 | 4 | day_idx 超出范围 |
| 5 | 开始/结束时间超出范围 | 5 | 映射到的日计划是空的 |
| 6 | sh%/sl% 超出范围 | 6 | EMS 不在 tou_plan 模式 |
| 7 | pc/pd 超出范围 | | |
| 8 | day_idx 超出范围 | | |
| 9 | 结束时间必须晚于开始时间 | | |
| 10 | EMS 不在 tou_plan 模式 | | |

> **一次下发失败后，设备上的计划完全不变。** 卡片现在会明确写出
> 「the plan on the device was NOT changed」，不会再显示一句笼统的「保存并激活完成」。

### 三种模式的实际含义（容易误解）

| 模式 | 固件常量 | 实际行为 |
|---|---|---|
| 强制充电 `mode=1` | `EMS_BAT_CHG_FIRST` | 光伏 + 电网一起给电池充，充到 `sh%` 停 |
| 光伏充电 `mode=2` | `EMS_PV_CHG` | 只用光伏充，不取电网 |
| 放电 `mode=4` | `EMS_SELF_USE` | **不是强制卖电**。自发自用 + 允许放电，`pd` 只是上限 |

> 「放电」段之所以经常只输出几十瓦，是因为它等于「自发自用」：没有电表时负载就是
> 并网口的实际负载，91 W 的负载自然只放 91 W。这不是 bug。

> `pc` 有物理上限：单包 `pack_count=1` 时充电封顶 500 W，设 800/1200 也只出 500 W。

### ⚠ 回读不可靠（历史坑，现已规避）

`tou_plan/status` 的 attributes **只在成功收到 get 回包时更新**；get 失败、超时、或
EMS 不在 `tou_plan`（回 `{\"status\":1,\"err_msg\":\"general error\"}`）时，
HA 实体**保留上一次的旧属性**。所以旧版本卡片会显示旧计划，让人误以为「配置被回滚」
——实际没有回滚，只是读到旧缓存。

现在 `_fetchPlan()` 会同时校验 `last_updated` **和** 回包里的 `week` 字段，二者不匹配
就报「no reply from the device」，不会拿旧值冒充新值。

> **为什么要有 EMS 门控。** 早期固件没有给 `ems_mode` 提供 `state_topic`，集成会给它
> 补一个**自维护的 retained 状态话题** `hoymiles/<dev_id>/ems_mode/state`：
>
> - 任何人向 `…/ems_mode/command` 下发后，集成立即回显到该话题 → 界面 / 卡片即时刷新；
> - 同时跟随 `system/state` 里的 `ems_mode`（设备真实运行模式，5 分钟周期）进行纠正，
>   所以设备侧超时自动回退到 `general` 也能反映出来。
>
> 为什么不直接把 `state_topic` 指向 `system/state`：该话题只有 5 分钟周期，而本卡片
> 是用 select 状态做门控的，那样会让「切到 tou_plan」后最多卡 5 分钟。

## 8. `custom:hoymiles-energy-sankey`

基于长期统计绘制的「源 → 汇」能量流桑基图。

```yaml
type: custom:hoymiles-energy-sankey
dev_id: MSA-280520260806
title: 能量流
language: zh
range: today
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dev_id` | string | — | **必填** |
| `title` | string | 本地化标题 | 卡片标题 |
| `language` | `en` \| `zh` \| `de` | *工具栏切换* | 钉死本卡片语言；不填则跟随工具栏里的选择（默认英文）。`zh-Hans` / `zh-Hant` / `zh-CN` 都选中文，`de-AT` / `de-CH` 选德语。 |
| `range` | `today` \| `7d` \| `30d` \| `month` | `today` | 时间范围 |
| `balancer_label` | string | 本地化 | 「损耗 / 未计量」节点的自定义名称 |
| `show_toolbar` | bool | `true` | `false` 隐藏时间段切换栏 |
| `ribbon_gap` | number (px) | `3` | 带宽之间的白色间隙 |
| `ribbon_opacity` | number | `0.5` | 带宽透明度（0~1） |
| `icons` | map | — | 逐节点 emoji 覆盖，如 `pv: "☀️"` |
| `statistics` | string \| list \| map | — | 覆盖默认 `statistic_id`。值可以是单个 id 或数组，数组会被求和 |

### 数据来源

卡片调用 HA 官方的 WebSocket 统计接口读取**长期统计**：

```
recorder/statistics_during_period
  statistic_ids: [...]   # 本设备的能量传感器
  period: "day"
  units: {energy: "kWh"} # 由服务端换算单位
  types: ["change"]      # HA 已算好的区间增量
```

因此：

- **不接触** recorder 数据库文件（不读 SQLite、不受 schema 迁移影响）
- **不需要管理员权限**（`statistics_during_period` 没有 `require_admin`）
- 只依赖 recorder 集成（属于 `default_config`）
- 渲染是自绘 SVG，**不依赖 CDN**，离线也能用

### 交互

点击某条带可以把这条流单独高亮；点击某个节点方框可以高亮所有与它相连的带。
其余部分变暗，并在详情面板列出涉及的流。再点同一目标（或点空白处）取消高亮。
这只是视图状态，数值不会改变。

### 关于「损耗 / 未计量」节点

桑基图要求流量守恒，而设备各端口是**独立计量**的（转换损耗、采样相位、
未计量负载都会造成差额）。卡片**不做归一化缩放**，而是把差额显式画成一个
节点（正差额记为「损耗/其他」，负差额记为「未计量」），
保证图面守恒且各条数值真实。

### 渲染精度说明

两侧各是一列节点方框。由于设备每个端口独立计量，带宽背后的**走线并非实测**：
它是在禁止「电池放电 → 电池充电」这类不可能环路的前提下，用迭代比例拟合
把每个源按比例分摊到各个汇上得到的估计值。请把带宽当作尽力而为的归因，
而不是计量事实。

### 与官方能源仪表盘的关系

HA 自带能源仪表盘有 Sankey 风格的「能量分布」卡片，但节点固定为
**光伏 / 电网 / 电池 / 家庭** 四类。配置方法：

| 位置 | 建议实体 |
|---|---|
| 太阳能 | `sensor.<dev>_system_pv_energy_today` |
| 电网受电 | `sensor.<dev>_grid_on_energy_in_total` |
| 电网送电 | `sensor.<dev>_grid_on_energy_out_total` |
| 电池充电 | `sensor.<dev>_battery_charge_energy_today` |
| 电池放电 | `sensor.<dev>_battery_discharge_energy_today` |

> **优先用 `*_total` 累计口径**（`grid_on_*` / `inv_*` 的 `etin` / `etout`）。
> `*_today` 型每天清零，HA 在**长时间停机后**会把「跨天下降」识别为设备重置，
> 中间天数的增量会丢失；累计型没有这个问题。

设备特有的 **EPS / 插座 / 离网** 端口官方模型装不下，那部分用本卡片展示。
